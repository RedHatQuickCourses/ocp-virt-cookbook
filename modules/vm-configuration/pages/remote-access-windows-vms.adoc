= Accessing Your Windows 11 VM on Red Hat OpenShift via Remote Desktop
:navtitle: Remote Access to Windows VMs via RDP

== Overview

This tutorial guides you through configuring external Remote Desktop Protocol (RDP) access to your Windows 11 virtual machine running on OpenShift. After completing this guide, you will be able to connect directly to your VM using Windows Remote Desktop, providing a more seamless and feature-rich experience than the VNC console.

== What problem does this solve?

Users who need to access Windows VMs hosted on Red Hat OpenShift Virtualization via Microsoft Remote Desktop.

== Use Cases

[cols="1,2"]

== Network Topology

The following diagram shows how an RDP client reaches a Windows VM running in OpenShift Virtualization. Two service exposure options are supported:

----
┌─────────────────────────────────────────────────────────────────┐
│ RDP Client (Windows Workstation)                                │
│   Remote Desktop Connection on port 3389                        │
└────────────────────────┬────────────────────────────────────────┘
                         │
             ┌───────────┴───────────┐
             │                       │
             ▼                       ▼
┌─────────────────────┐   ┌──────────────────────────────────────┐
│ Option A:           │   │ Option B:                            │
│ MetalLB LoadBalancer│   │ NodePort Service                     │
│ Dedicated VIP       │   │ Worker Node IP + port (30000-32767)  │
│ port 3389           │   │ mapped to port 3389                  │
└──────────┬──────────┘   └───────────────┬──────────────────────┘
           │                              │
           └──────────────┬───────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────────┐
│ Kubernetes Service (port 3389)                                  │
│   selector: vm.kubevirt.io/name: <your-vm-name>                 │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ virt-launcher Pod (OpenShift Virtualization runtime)            │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ Windows 11 VM                                                   │
│   RDP Server on port 3389                                       │
│   Internal IPs: 10.0.2.2 (guest NIC) / 10.128.x.x (pod)         │
└─────────────────────────────────────────────────────────────────┘
----

NOTE: The VM's internal IPs (10.0.2.2 and 10.128.x.x) are not externally routable. The Kubernetes Service handles the mapping from the external endpoint to the VM.

== Prerequisites

* Windows 11 VM successfully deployed on OpenShift
* Access to OpenShift web console or `oc` CLI
* VM accessible via VNC console
* Administrative access to the Windows 11 VM
* Local Windows machine with Remote Desktop Connection client

== Tutorial Steps

=== Step-by-Step Configuration

==== Step 1: Enable Remote Desktop in Windows 11

. **Access VM Console**
+
Log into your Windows 11 VM using the OpenShift VNC console
. **Open System Settings**
+
Right-click the **Start Menu**
+
Select **System**
. **Configure Remote Desktop**
+
Navigate to **Remote Desktop** in the left menu
+
Toggle **Remote Desktop** to **On**
+
Click **Confirm** when prompted
+
**Note the PC name** displayed for later use

==== Step 2: Expose VM to External Network

You need to create a service exposing RDP port 3389. Choose your preferred method:

===== Option A: OpenShift Web Console (Recommended)

. **Navigate to Services**
+
[source,text]
----
OpenShift Console → Your Project → Networking → Services
----
. **Create New Service**
+
Click **Create Service**
+
Configure the following:
+
|===
| Field | Value | Description

| **Service Type**
| `LoadBalancer`
| Provides dedicated external IP

| **Service Name**
| `win11-rdp-service`
| Descriptive service name

| **Selector**
| `vm.kubevirt.io/name: <your-vm-name>`
| **Critical**: Replace with actual VM name

| **Port**
| `3389`
| Service exposed port

| **Target Port**
| `3389`
| RDP port on Windows VM

| **Protocol**
| `TCP`
| Required for RDP
|===
+
NOTE: If LoadBalancer is unavailable, use `NodePort` (assigns port 30000-32767)
. **Create the Service**
+
Click **Create**
+
Note the assigned port if using NodePort

===== Option B: Command Line Interface

. **Download Service Definition**
+
xref:attachment$remote-access-windows-vms/rdp-service.yaml[Download rdp-service.yaml]
+
[source,yaml]
----
apiVersion: v1
kind: Service
metadata:
  name: win11-rdp-service
spec:
  selector:
    vm.kubevirt.io/name: your-vm-name  # REPLACE with your VM's actual name
  ports:
    - protocol: TCP
      port: 3389
      targetPort: 3389
  type: LoadBalancer  # or NodePort
----
. **Apply Configuration**
+
[source,bash,role=execute]
----
oc apply -f rdp-service.yaml
----

==== Step 3: Obtain Connection Details

===== For LoadBalancer Service:

. Navigate to **Networking → Services**
. Locate `win11-rdp-service`
. Record the **External IP** address

===== For NodePort Service:

. Find your service and note the assigned **NodePort** (e.g., `31234`)
. Get worker node external IP:
+
[source,bash,role=execute]
----
oc get nodes -o wide
----
+
Look for **EXTERNAL-IP** column

==== Step 4: Connect via Remote Desktop

. **Open Remote Desktop Connection**
+
Search for "Remote Desktop Connection" on your local Windows machine
. **Enter Connection Information**
+
|===
| Service Type | Computer Field Format | Example

| **LoadBalancer**
| `<External-IP>`
| `203.0.113.5`

| **NodePort**
| `<Node-External-IP>:<NodePort>`
| `203.0.113.10:31234`
|===
. **Initiate Connection**
+
Click **Connect**
+
Enter your Windows 11 VM credentials when prompted

== Security Considerations

Exposing RDP directly to the internet creates significant security risks. 
These access controls limit the exposure of your RDP service by controlling who can reach it and how. 


*Choose one for access control:*

* *NetworkPolicy* — applies when you have an external service exposed; restricts which source IPs can reach port 3389.
* *RDP over SSH Tunnel* — applies when you want to avoid external exposure entirely.

*In addition, apply the following to secure the connection itself:*

* *Trusted RDP Listener Certificate* — secures the connection itself by configuring a certificate that clients can use to verify the VM's identity.
* *Network Level Authentication* — a Windows-side setting that hardens the RDP service by requiring authentication before a session is established.

=== Restrict Access with NetworkPolicy

Create a NetworkPolicy to limit RDP ingress to specific source IP ranges:

xref:attachment$remote-access-windows-vms/restrict-rdp-networkpolicy.yaml[Download restrict-rdp-networkpolicy.yaml]

[source,yaml]
----
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: restrict-rdp-access
  namespace: <your-namespace>
spec:
  podSelector:
    matchLabels:
      vm.kubevirt.io/name: <your-vm-name>
  policyTypes:
  - Ingress
  ingress:
  - from:
    - ipBlock:
        cidr: 203.0.113.0/24
    ports:
    - protocol: TCP
      port: 3389
----

Replace `203.0.113.0/24` with your organization's allowed IP range.

WARNING: If you use this policy to allowlist RDP client IPs, set
`spec.externalTrafficPolicy: Local` on the RDP Service. This preserves the
client source IP for supported `NodePort` and `LoadBalancer` configurations.
For details, see
link:https://kubernetes.io/docs/tutorials/services/source-ip/[Using Source IP,window=_blank].

Set this field on the RDP Service with:

[source,bash,role=execute]
----
oc patch service <your-rdp-service-name> --type merge -p '{"spec":{"externalTrafficPolicy":"Local"}}'
----

NOTE: This policy allows TCP port 3389 from the specified source range and blocks other ingress to the selected VM pod. If the VM must receive traffic on additional ports, add those ports to this policy. NetworkPolicies are additive: if another policy selecting the same VM pod allows broader ingress, that traffic remains allowed. Check for overlapping policies before relying on this allowlist. For details, see
link:https://kubernetes.io/docs/concepts/services-networking/network-policies/[Kubernetes NetworkPolicies,window=_blank].

=== RDP over SSH Tunnel

As an alternative to exposing port 3389 directly, tunnel RDP traffic through an SSH connection. The SSH tunnel encrypts the session and avoids creating an externally accessible service. The exact steps depend on your network topology and how your cluster is accessible. Refer to your SSH client documentation for port forwarding instructions.

=== Configure a Trusted RDP Listener Certificate

By default, Windows generates a self-signed certificate for the RDP listener, which causes clients to show an untrusted certificate warning. In production environments, replace it with a certificate signed by a CA that your RDP clients trust. The listener certificate verifies the server's identity; it does not authenticate the user. Clients must trust the issuing CA and validate the server identity used for the connection to prevent man-in-the-middle attacks.

For step-by-step instructions, refer to the link:https://learn.microsoft.com/en-us/troubleshoot/windows-server/remote/remote-desktop-listener-certificate-configurations[Microsoft documentation on Remote Desktop listener certificate configurations,window=_blank].

=== Enable Network Level Authentication

Network Level Authentication (NLA) requires users to authenticate before a full RDP session is established. This reduces the attack surface by rejecting unauthenticated connection attempts before any desktop is rendered.

In the Windows 11 VM:

. Open **System Settings** and navigate to **Remote Desktop**.
. Enable **Require devices to use Network Level Authentication to connect**.

NOTE: Regardless of which controls you apply, use strong passwords and monitor RDP access logs regularly.

== Verification & Troubleshooting

=== Connection Success Indicators

* Remote Desktop client connects without timeout
* Windows 11 desktop appears with full functionality
* Mouse and keyboard input responsive
* Audio/clipboard redirection works (if configured)

=== Common Issues & Solutions

|===
| Issue | Possible Cause | Solution

| **Connection timeout**
| Service not created properly
| Verify service exists and has external IP

| **Connection refused**
| RDP not enabled in Windows
| Re-enable Remote Desktop in Windows settings

| **Wrong credentials**
| Incorrect VM login details
| Verify username/password via VNC console

| **Service has no external IP**
| LoadBalancer not available
| Switch to NodePort service type
|===
